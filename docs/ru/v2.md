# KVN v2 — TCP-first stealth transport

KVN v2 — единственный протокол в 2.0.0, **несовместимый с v1**. Старые v1-сборки доступны только в GitHub Releases и не входят в текущее дерево.

## Архитектура

- TLS 1.3 + HTTP/2.
- TCP-потоки завершаются на клиенте через gVisor netstack и уходят отдельными HTTP/2-стримами.
- Сервер открывает обычные TCP-сокеты к target; userspace TCP stack на сервере не нужен.
- UDP по умолчанию идёт best-effort HTTP/2 streams.
- При `quic_enabled: true` UDP идёт через **одно общее QUIC-соединение**: datagrams с flow ID, без отдельного stream/канала на каждый UDP-flow. Если QUIC недоступен — fallback на HTTP/2 UDP.
- Bearer проверяется до stream; невалидный запрос получает fallback-сайт.
- Один HTTP/2 client переиспользуется для всех flow; TLS-соединения не создаются на каждый поток.

## Сервер

```yaml
listen: 0.0.0.0:443
tls:
  cert: /etc/kvn-ws/certs/server.pem
  key: /etc/kvn-ws/certs/server-key.pem
auth:
  tokens:
    - name: default
      secret: change-me
fallback:
  title: Acme Telemetry
  # upstream: https://real-site.example
max_streams: 512   # для 1 CPU / 1–2 GB
```

Запуск:

```bash
./bin/kvn-server --config configs/server.yaml
```

## Клиент: standalone или kvn-web

`kvn-client` — полноценный standalone entrypoint: достаточно конфига и запуска бинаря. kvn-web — опциональный UI, который запускает тот же v2 client in-process.

1. Запусти `kvn-web` с правами root (TUN/routes/resolv.conf).
2. Add server:
   - Server URL: `https://host:443`
   - Token
   - Mode: `tun`
   - TUN Address: `10.66.0.2/24`
   - TUN Gateway: `10.66.0.1`
3. Routing/DNS/TLS — в отдельных вкладках.
4. Connect.

`kvn-web` — единственный UI в 2.0.0 и он v2-only. Настройки хранятся в `~/.config/kvn/config.yaml`; v1 `config.yaml` не читается и не изменяется (кроме одноразового импорта записей с `protocol: v2`). v1 доступен только в старых релизах.

CLI-диагностика:

```bash
sudo ./bin/kvn-client --config configs/client.yaml
```

## Android 2.0: выбранный путь

- Go v2 data plane компилируется под `android/arm64` и `android/amd64` с `CGO_ENABLED=0`; gVisor/TCP stack не требует изменений протокола.
- Рекомендуемый путь: `gomobile bind` общего Go-core (`src/mobile`) + `VpnService` fd из Kotlin. Kotlin настраивает TUN/routes/DNS, Go читает/пишет fd и держит v2 HTTP/2/QUIC.
- DNS routing/fake-DNS/direct delivery сохраняются на Kotlin-стороне; v2 core не должен их дублировать.
- QUIC-UDP на Android — не обязателен для 2.0 MVP; используется v2 HTTP/2 UDP fallback, QUIC можно добавить после TCP/TUN.
- Требования окружения для AAR: Android SDK + **NDK 28.x** и `gomobile`; NDK 28.2 уже установлен, `gomobile`/AAR — следующий шаг.

### TUN assignment

Сервер выдаёт уникальный `tun_address` из пула и общий `tun_gateway`. Клиент не хранит локальные TUN-поля и не поднимает TUN, если assignment недоступен.

```yaml
tun:
  subnet: 10.66.0.0/24
  range_start: 10.66.0.2
  range_end: 10.66.0.254
  gateway: 10.66.0.1
  lease_ttl_sec: 300
```

## QUIC datagrams для UDP

QUIC — один общий канал на клиента для всех UDP-flow. Каждый datagram содержит flow ID; сервер держит UDP-сокет на flow. Это не полный HTTP/3 framing, а QUIC datagram side channel с ALPN `h3`.

```yaml
quic_enabled: true
quic_endpoint: vpn.example.com:8443
mtu: 1200   # чтобы UDP-пакеты помещались в QUIC datagram
```

На сервере:

```yaml
quic_listen: 0.0.0.0:8443
```

Если QUIC заблокирован, клиент автоматически использует HTTP/2 UDP streams.

## Split tunnel

- `routing.exclude_ranges`/`exclude_ips` добавляются как OS exclude-маршруты.
- `routing.exclude_domains` учитываются DNS-proxy: direct-домены резолвятся напрямую и получают exclude-маршрут.
- DNS upstream идёт напрямую (не через VPN) в текущей версии.

## Ограничения

- v2 несовместим с v1 wire-протоколом.
- ICMP echo (`ping`) поддерживается через ICMP-proxy на сервере; `traceroute` и прочие ICMP-типы могут не работать.
- UDP — best-effort поверх HTTP/2/TCP; для видео/голоса H3 datagrams ещё не реализованы.
- TUN требует root/CAP_NET_ADMIN.
- gVisor работает на клиенте; сервер не использует userspace TCP stack.
- На 1 CPU / 1–2 GB ставь `max_streams: 256–512`; узкое место — TLS/HTTP2 CPU, не RAM.
- Relay v2, Android v2 и H3 — отдельные фазы.
